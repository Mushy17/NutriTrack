## What I Learned / What Did Not Work

### What I Learned

- How controlled React forms manage input values through `useState`, `value`, and `onChange`.
- How to implement custom form validation before sending data to an API.
- Why `event.preventDefault()` is necessary when submitting forms in React.
- How GET, POST, PATCH, and DELETE implement CRUD operations.
- How to centralize HTTP requests through a reusable `request()` function.
- Why React state should be updated only after the server confirms an operation.
- Why newly created entry IDs should be generated by the server instead of the frontend.
- How to prevent duplicate submissions by disabling the submit button while saving.
- How to preserve form values and display errors when an API request fails.
- How `data-testid` attributes allow automated tools to identify interface elements.
- How `tw.json` maps application-specific fields to automated evaluation requirements.
- Why separating form logic into a dedicated component improves code organization and maintainability.

### What Did Not Work / Challenges

- The original Add Entry form updated React state locally and did not persist new entries after refreshing the page. It was replaced with API-based saving.
- Refactoring the form initially caused a `Statement expected` syntax error because code from the previous implementation remained in `App.jsx`. Removing the obsolete code and integrating `EntryForm.jsx` resolved the issue.
- Completion toggling and deletion initially modified only local state. PATCH and DELETE requests were added to persist these changes.
- During DELETE testing, the predefined Morning Run activity was accidentally removed from `db.json`. The entry was restored manually.
- The automated evaluation requirements introduced additional attributes and a `tw.json` configuration file that were not present in previous stages.
- Existing dashboard statistics, weekly analytics, responsive styling, and light/dark themes needed to remain functional throughout the refactoring.

The implemented Stage 7 CRUD functionality and the presence of automated evaluation attributes were verified during development. The application now supports persistent entry creation, completion updates, and deletion through the mock REST API.
