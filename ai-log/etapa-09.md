## What I Learned / What Did Not Work

### What I Learned

- How to create a backend project using Node.js and Express.
- How to organize Express routes using Router.
- How to implement REST endpoints with GET, POST, PATCH, and DELETE.
- How to access URL parameters using req.params.
- How to read JSON request bodies using req.body and express.json().
- How to validate input data on the server.
- How to return appropriate HTTP status codes and JSON error messages.
- How to implement centralized error handling.
- How to configure CORS for frontend-backend communication.
- How to test an API independently using PowerShell.
- How to separate app.js from server.js.
- How to replace json-server without rewriting the React components.
- How npm uses package.json and package-lock.json.
- Why data stored in server memory is lost after restarting the backend.

### What Did Not Work / Challenges

- The initial package.json generated by npm init used CommonJS and required modification to support ES modules.
- The backend had to use the same /entries resource and port 3001 as the existing frontend.
- The API validation needed to match the NutriTrack entry model rather than the generic TaskFlow example.
- PowerShell commands required different syntax from the curl examples in the guide.
- The frontend initially displayed generic HTTP error messages; api.js was updated to read the error message returned by Express.
- json-server needed to be removed from both package.json and package-lock.json.
- Data persists across frontend refreshes but resets when the backend restarts, because Stage 9 uses in-memory storage.

## Result

The NutriTrack frontend now communicates with a custom Express backend. All five REST operations, validation, error handling, and frontend interactions were tested successfully.

The implementation prepares the project for Stage 10, where in-memory storage will be replaced by MariaDB.
